# 传埔斯 · 居民档案

《谁在替谁完成？》的活动预热页。

一份关于一位长期居住者的资料，由城内几位居民整理。分成六页，从资料本身开始，
最后落到一套还在运行的系统面板上。

## 页面

| 文件 | 内容 |
| --- | --- |
| `index.html` | 大站：分页列表 + 每一页的进度 |
| `city.html` | 传埔斯 |
| `life.html` | lie_fish |
| `places.html` | Miku小屋 · 鱼鱼中店 |
| `people.html` | 认识他的人 |
| `panel.html` | 系统面板 + 反馈（工单） |
| `open.html` | 入口：输入 key，对了打开那一份日记，读完接 TRUE END |
| `_old/` | 第一版三个页面，留档，未改动 |

`clock.js` 只管页头那口钟。`app.js` 只在 `panel.html` 上用。

## 分页进度

`state.js` 把「看过哪几页、解开哪几页」记在浏览器本地（localStorage），
大站（`index.html`）读它显示状态。没有后端，换浏览器或者清了浏览器数据就重来。

各页什么时候标：

| 分页 | 打开 | 解开 |
| --- | --- | --- |
| 传埔斯 / lie_fish / 两处地方 / 认识他的人 | 已读 | —— |
| 系统面板 | 已读 | 交过一条工单 |
| 入口 | 已读（未解开） | 输对 key |

## 本地预览

静态页，没有构建步骤，直接开 `index.html` 也行。想更接近线上就起个服务：

```
python -m http.server 8123
```

## 反馈（工单）

`panel.html` 底部的反馈表单是**纯前端**的：提交后在浏览器本地生成一张工单凭条，
玩家自己复制、发回来。没有后端，页面上不会上传任何东西。

## 入口那一页

`open.html` 用 SHA-256 校验密钥，仓库里只有哈希，没有密钥明文。

归一化规则：去掉空格和横杠一类的分隔符，再转大写。
换密钥时，把新密钥按这个规则算出的 SHA-256 替换 `GOOD_ENDING_HASHES` 里的那一行即可。

## 音频

`audio-01.ogg` 是好结局的音乐：只在 `open.html` 输入对 key、那份日记打开的那一刻开始放，
页面上那个「音乐：开／关」按钮可以随时停。别的页面上不响。

旧版用的 `flatten-the-curve.flac` 现在没有任何页面引用它（16 MB，可以删）。

公开仓库之前请确认两首曲子都拥有公开传播权限。
